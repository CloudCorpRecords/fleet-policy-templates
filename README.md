# fleet-policy-templates

**Least privilege at fleet scale: one declarative manifest in, one scoped 1Claw vault path + one read-only policy per tool out — with a linter that fails the run before a `**` ever ships.**

Built with [1Claw](https://1claw.co) for the **1Claw Creator Contest** (Nov 1 – Dec 1, 2026). Companion to Secretless Agent (same contest workspace): that project proves the pattern for *one* agent and *one* secret; this one proves it for a *fleet*.

---

## The problem

One agent with one scoped policy is a demo. A real builder runs dozens of agents wired to hundreds or thousands of tools — and hand-writing a vault path + policy per tool does not scale. The failure mode is predictable: someone gets tired, grants `**` ("just make it work"), and the fleet is one prompt injection away from every secret it can reach.

## What this project does

You write **one JSON manifest** — agents, the tools each agent uses, and the secret each tool needs **by name, never by value**:

```json
{
  "fleet": "starter-fleet",
  "agents": [
    {"name": "research-agent",
     "tools": [{"name": "web-search", "secret_name": "search-api-token"},
               {"name": "doc-store",  "secret_name": "doc-store-token"}]},
    {"name": "ops-agent",
     "tools": [{"name": "status-pager", "secret_name": "pager-token"}]}
  ]
}
```

`fleetclaw.py` compiles it into:

1. **One vault path per tool** — `fleet/<agent>/<tool>/<secret-name>` (e.g. `fleet/research-agent/web-search/search-api-token`). No shared paths.
2. **One read-only 1Claw policy per (agent, tool) pair** — that agent, `read` only, pattern exactly that path. No wildcards.
3. **A plan/apply runner** — plan shows create/skip/drift; apply is **idempotent** (re-apply is a no-op), reports drift, and **never widens an existing grant** silently.

And `policylint.py` fails the run on dangerous shapes *before* anything is applied:

| Rule | Fails on |
|---|---|
| `double_star` | any `**` pattern in a path or policy |
| `write_permission` | any permission other than `read` on a secret path |
| `shared_path` | one vault path claimed by two different agents |
| `orphan_tool` | a tool with no owning agent |

Negative fixtures for every rule live in `fixtures/` — each one must fail lint, and the tests assert that they do.

## Scale proof (MOCK dry run, real numbers)

A deterministic generator (`gen_fleet.py`, seed 42) emits a **1,000-tool manifest across 50 agents** (synthetic names only). The MOCK dry run over it — captured in `output/dry_run_1000.log` and `output/coverage_report.json`:

```
Coverage (MOCK): 1000 tools, 1000 unique paths, 0 shared, 0 wildcards, 0 double-star, 1000 policies, lint_clean=True
First apply:  1000 policies created (50 agents)
Second apply: 0 created, 1000 skipped, 0 drift  (idempotent)
```

## Files

| File | Role |
|---|---|
| `fleetclaw.py` | CLI: `compile` / `lint` / `plan` / `apply` / `dry-run`. Manifest → vault paths + policies; MOCK/LIVE runner |
| `policylint.py` | Dangerous-shape linter (rules above); module + CLI |
| `gen_fleet.py` | Deterministic seeded generator (default: 50 agents × 20 tools = 1,000) |
| `mock_client.py` | Local in-memory shim with the same interface as the `oneclaw` SDK subset used here (approach copied from `../secretless-agent/mock_client.py`, our own code) |
| `manifest.schema.json` | JSON Schema for the manifest format |
| `examples/starter.json` | 3-tool starter manifest |
| `fixtures/bad_*.json` | Negative fixtures — one per lint rule, each must fail |
| `tests/test_fleet.py` | 11 tests: compile correctness, each lint rule, idempotency, never-widens, generator determinism, 1,000-tool dry run |
| `fleet_1000.json` | The generated 1,000-tool manifest (regenerated by `gen_fleet.py`; see Honesty notes) |
| `output/` | Captured MOCK dry-run log + coverage report |

## Run it — MOCK mode (no account, 30 seconds)

```bash
cd fleet-policy-templates
python fleetclaw.py lint    --manifest examples/starter.json
python fleetclaw.py dry-run --manifest examples/starter.json
python gen_fleet.py --out fleet_1000.json
python fleetclaw.py dry-run --manifest fleet_1000.json --out output/coverage_report.json
python -m pytest tests/ -v        # if you have pytest
python tests/test_fleet.py        # stdlib-only fallback runner (11 tests)
python policylint.py fixtures/bad_double_star.json   # must FAIL — that's the point
```

No key, no network, no install — everything is stdlib-only. MOCK mode uses the local shim and says so in every banner; it is never presented as live 1Claw.

## Run it — LIVE mode with a real 1Claw key (5 steps)

1. Sign up at [1claw.co](https://1claw.co) and create a **user API key** (it starts with `1ck_`).
2. `pip install -r requirements.txt` — installs the official `oneclaw` SDK from PyPI.
3. Copy `.env.example` to `.env` and set `ONECLAW_API_KEY` to your key (`.env` is git-ignored; or export it in your shell instead — note the code reads the env var itself and passes it to `create_client`, because the SDK does not read env vars).
4. Review the plan against the real account: `python fleetclaw.py plan --manifest examples/starter.json --live`
5. Apply it: `python fleetclaw.py apply --manifest examples/starter.json --live` — then run it again and watch it report all-skip. Drift, if any, is reported, never widened.

## Threat note (Security Ship Gate)

- **Public surface:** none. This is a local CLI; it opens no ports and serves no pages.
- **Secrets in the repo:** none. The manifest names secrets, never values; the generator emits synthetic names only; only `.env.example` placeholders are committed and `.env` is git-ignored.
- **What an attacker would want:** the vault key (`ONECLAW_API_KEY`). It is never written to disk by this code and never appears in plans or reports — plans contain paths and policy shapes only.
- **The risk this tool itself creates, stated plainly:** a manifest compiler is a privilege-minting machine. That is why lint runs *before* plan/apply and apply refuses a manifest that fails lint, why compiled patterns are exact paths (never `*`/`**`), why apply never widens an existing grant, and why every plan is a reviewable, diff-able artifact. A broader existing policy is reported as drift for a human to resolve — the tool does not silently fix or replace it.
- **Residual risks (recorded, not hidden):** MOCK mode is a teaching shim, not a security boundary — use LIVE mode for anything real; the compiler cannot judge whether an agent *should* have a tool, only that its grant is exactly scoped — manifest review is still a human job; LIVE mode was not exercised during the contest build (no key was used), so the LIVE path is documented and code-reviewed against the SDK interface, while all *measured* claims in this README come from MOCK runs.
- **Honeypot/canary:** not applicable — no live production surface. The `fixtures/bad_*.json` files play the canary role: if a refactor ever lets one pass lint, the test suite fails loudly.

## Honesty notes

- Every number above (1,000 tools / 1,000 unique paths / 0 shared / 0 wildcards / lint clean / idempotent re-apply) comes from an actual MOCK run captured during the build; see `output/`. MOCK is labelled MOCK everywhere it appears.
- During the build session, the VM's write-guard blocked in-session Python file writes (EPERM), so `fleet_1000.json` regeneration on disk was delegated to a one-time verification cron (`fleet-policy-verify-run`) that re-runs the generator, the 1,000-tool dry run, and the full test suite and writes the logs to `output/`. The coverage numbers in `output/coverage_report.json` are from the verified in-session in-memory run of the same deterministic manifest (seed 42).
- No real secrets, no real MCP servers, no live fleet were involved. Synthetic manifest + MOCK proof; LIVE apply path documented above.
